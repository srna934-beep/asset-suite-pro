# خطة تنفيذ الوحدات الثلاث (العقارات، الأراضي والمزارع، المركبات والمعدات)

الطلب ضخم جداً (ثلاث وحدات مؤسسية كاملة). لن يتم حذف أو تغيير أي شيء موجود — كل ما يلي إضافة فوق الهيكل الحالي، وسيُنفّذ على 3 مراحل حتى يبقى النظام مستقراً بعد كل مرحلة.

## المرحلة 1 — الأساس والتوسّع الهيكلي

### قاعدة البيانات (هجرة واحدة)
- جدول `asset_types` قابل للتخصيص (نطاق: عقار / أرض / مركبة) مع أنواع جاهزة:
  - عقارات: سكني، تجاري، صناعي، فنادق، مستشفيات، مستودعات، مكاتب، متعدد الاستخدام.
  - أراضي: سكنية، تجارية، صناعية، زراعية، استثمارية، حكومية، مؤجرة، مزارع، بستان، مشاتل، بيوت محمية، مراعي.
  - مركبات: سيارة، شاحنة، باص، مقطورة، حفّار، بلدوزر، رافعة، رافعة شوكية، تراكتور، مولّد، قارب، معدات زراعية، آلات صناعية.
- التسلسل الهرمي للعقار: جدول `property_nodes` (نوع العقدة: مبنى / بلوك / دور) بشجرة `parent_id`، وربط `units.node_id` اختياري — الوحدات الحالية تبقى تعمل كما هي بدون عقدة.
- حقول إضافية اختيارية: `properties.type_id`, `lands.type_id`, `vehicles.type_id`, و`qr_code` لكل أصل.

### الواجهة
- إدارة الأنواع داخل الإعدادات (إضافة نوع مخصص).
- في تفاصيل العقار: تبويب «الهيكل» لإضافة مبانٍ/بلوكات/أدوار وربط الوحدات بها، مع شجرة قابلة للطي.
- بطاقة QR/باركود لكل أصل (توليد محلي + طباعة) وربطها بصفحة التفاصيل.

## المرحلة 2 — إدارة المزارع

### قاعدة البيانات
جداول جديدة مرتبطة بـ `lands` (تُفعّل تلقائياً عندما يكون نوع الأرض مزرعة/بستان/محمية/مراعي):
`farm_seasons`, `farm_crops`, `farm_trees`, `farm_operations` (زراعة، حصاد، ريّ، تسميد، مكافحة)، `farm_production`, `farm_inventory`, وربط العمال (`employees`) والمعدات (`vehicles`) بالمزرعة/الموسم.

### الواجهة
- تبويب «إدارة المزرعة» يظهر تلقائياً في تفاصيل الأرض الزراعية: المواسم، المحاصيل والأشجار، العمليات الزراعية، الإنتاج، المخزون، العمال والمعدات.
- حساب تلقائي للإنتاج والربحية وأداء الموسم، وربط كل مصروف/إيراد زراعي بالحركات المالية والميزانيات والأهداف.

## المرحلة 3 — المركبات والمعدات (التشغيل الكامل)

### قاعدة البيانات
`vehicle_assignments` (إسناد لمشروع/موظف/أصل)، `vehicle_drivers`، `fuel_logs`، `vehicle_maintenance_schedules` (دوري بالكيلومترات أو التاريخ)، وحقول عدّاد التشغيل.

### الواجهة
- تبويبات في تفاصيل المركبة: الإسناد، السائقون/المشغّلون، الوقود، جدول الصيانة، الرخص والتأمين، التكاليف التشغيلية (تكلفة/كم وتكلفة/ساعة).
- تنبيهات تلقائية: انتهاء تأمين/استمارة، صيانة مستحقة، عبر جدول `notifications` الحالي.

## التكامل (يُطبّق في كل مرحلة)
- المحاسبة: كل عملية جديدة (وقود، عملية زراعية، إنتاج) تُنشئ حركة في `transactions` بالربط الحالي `entity_type`/`entity_id` + `project_id`/`budget_id`.
- الصيانة، المشاريع، الموظفون، المهام، الأهداف، الميزانيات: ربط عبر المفاتيح الموجودة دون تغييرها.
- التقارير والتصدير CSV، البحث الشامل (Ctrl+K)، سجل التدقيق `audit_logs`، المرفقات، والصلاحيات (`permissions.ts`) — تُضاف مفاتيح الوحدات الجديدة لكل ذلك.

## تفاصيل تقنية
- كل جدول جديد: `GRANT` للأدوار + `RLS` + سياسات (قراءة للمصادَق، كتابة للمدراء عبر `has_role`) + `updated_at` trigger + `log_audit` للجداول المهمة.
- كل الحقول الجديدة على الجداول الحالية اختيارية (nullable) — لا كسر لأي شاشة قائمة.
- الوصول للجداول الجديدة عبر `sb()` بدون لمس `types.ts` أو `client.ts`.
- التوسّع المستقبلي (ثروة حيوانية، دواجن، أسماك، IoT، تحليلات AI): تُترك نقاط ربط عبر `asset_types` القابل للتخصيص و`farm_operations.kind` المفتوح، بدون بناء واجهات لها الآن.

سأبدأ بالمرحلة 1 (الهجرة ثم الواجهات) بعد الموافقة، ثم أكمل المرحلتين 2 و3 بالتتابع.
